# OctoAcme Project Management Docs

This README provides a short summary of OctoAcme's project management processes and direct links to the full process documents stored in the docs/ folder.

## Quick summary of OctoAcme project management processes

OctoAcme runs iterative, customer-focused projects with clear ownership and measurable outcomes. The lifecycle progresses through initiation, planning, execution and tracking, release and deployment, and retrospective cycles that drive continuous improvement. Teams focus on delivering small, testable increments, defining acceptance criteria and a clear Definition of Done, and using data to measure outcomes.

Project work is managed on a visible project board and via small, reviewable pull requests that include issue links and acceptance criteria. Planning activities create a prioritized backlog and release plan while tracking dependencies and risks in a Risk Register. Releases are categorized (patch, minor, major) and require pre-release checks, rollback plans, release notes, and post-deploy verifications.

Clear roles and communication cadence help maintain alignment: Product Managers define outcomes and priorities, Project Managers coordinate delivery and escalations, Developers implement and test changes, QA validates acceptance, and stakeholders provide approvals and inputs. Regular ceremonies — daily standups, weekly delivery syncs, demos, and retrospectives — plus explicit escalation paths ensure transparency and quick resolution of blockers.
